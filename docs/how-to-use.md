# How to use these tools

A short, tool-agnostic path from "I want a video" to a first result. Each step points to the part of a card to read.

1. **Pick a goal.** Use the [tour](../tour/README.md) (by goal) or the [category pages](../README.md#categories).
2. **Read the card.** Check, in this order: License (does it allow your use? the `NC` marker means non-commercial only, and `—` means no license file), Install (what it changes on your machine), Stack (what else you must install, for example Node.js or ffmpeg), and Safety.
3. **Install** using the method the card shows, or one of the standard methods in [install](install.md). Read any script before you run it; see [safety](safety.md).
4. **Start small.** Several READMEs recommend a short sample first. For example, SeeCut's README suggests trying the first 20-30 seconds before a full video, and notes a 25-second sample takes about an hour.
5. **Expect approval gates.** Many tools stop and ask you to approve a script, subtitles or storyboard before rendering (for example [Paper-Cut](../skills/aijiduonadegou__Paper-Cut.md) and the talking-head tools). That is a feature; budget time for it.
6. **Watch the bill.** Tools that call hosted services (avatars, text-to-speech, image and video models) need accounts and can cost money per second or per call. The cost is in the README, not in this list.
7. **Keep the output reproducible.** Prefer tools that produce a project (Remotion or HyperFrames) so you can re-render, diff and tweak instead of regenerating from scratch.

Everything in this list is copied from READMEs and was not executed by us. If a step fails, the tool's own issue tracker is the right place to ask.
